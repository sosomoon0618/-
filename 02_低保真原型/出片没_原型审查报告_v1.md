# 出片没｜低保真交互原型审查报告 v1

**审查对象**：[出片没_低保真交互原型_v2.html](出片没_低保真交互原型_v2.html)  
**对照文档**：交互确认单 v1、姿势库与主题单 PRD v1、拍摄参考与照着拍 PRD v1  
**端形态**：移动 H5 / PWA 黑白灰低保真原型  
**审查方式**：产品设计完整性 + 消费者任务流/理解成本审查。当前环境无法在内置浏览器打开本地 `file:` 原型，因此交互结果基于 HTML 源码、确认单和 PRD 的静态核查；已完成 JavaScript 语法与核心入口存在性校验。

## 结论

**需修改后再进入 UI 设计规格。**

产品方向正确：个人姿势库与主题单已分层，“查看参考”先于“用手机照着拍”的路径也适合相机、朋友帮拍和手机自拍等多种现场情境。当前问题主要集中在**原型没有完整模拟已确认的核心数据关系**，继续做 UI 会掩盖这些交互缺口。

## 做得对的部分

### 产品设计

- **对象边界正确**：姿势库卡片与主题单引用分开，符合“长期总库 + 一次准备集合”的核心决策。
- **多设备拍摄情境正确**：先进入「查看参考」，用户可停留看图/开构图线；只有主动选择才进入手机相机。
- **范围克制**：没有把 AI、社区、行程管理和修图混进免费首版。
- **底部导航聚焦**：姿势库、主题单、照着拍、我的四项与首版任务一致。

### 消费者体验

- **低门槛入库**：导入页允许直接保存，不强迫用户填写字段。
- **主题单信息密度适中**：名称、人物穿搭、备注和图片的层级足够清楚，没有额外的任务管理噪音。
- **构图辅助线默认关闭**：不干扰看图，用户可在需要时打开。
- **风险操作有确认**：删除灵感卡、删除主题单的后果在原型中有对应确认弹窗。

## 必须修复（Blocker）

| 编号 | 位置 | 问题 | 为什么阻断 | 建议修改 |
|---|---|---|---|---|
| B1 | [主题单详情] →「直接导入图片」 | 模拟导入后只新建灵感卡并进入详情，**没有自动加入当前主题单**。 | 违背已确认规则：主题内直接导入必须同时进入姿势库并被当前主题单引用。用户会以为自己已把图加入本次清单，返回后却找不到。 | 在原型状态中保存 `sourceThemeId`；从主题单触发导入后，保存成功时同步创建主题引用，并返回当前主题单详情。 |
| B2 | [灵感卡详情] →「编辑标签」 | 点击后只显示“原型中模拟编辑标签”，没有标签选择、关键词输入、保存或取消。 | 手动轻量整理是无 AI MVP 的核心价值；没有该路径无法验证用户是否能理解「拍摄关键词」和结构化标签的关系。 | 增加「编辑灵感」底部弹层：展示地点、动作、人数、景别、拍摄关键词；至少模拟新增关键词、清除关键词、保存和取消。 |
| B3 | [主题单详情] →灵感卡详情→返回 | 原型未记录进入来源；从主题单打开卡片后，返回会回到姿势库。 | 用户在准备本次拍摄时会丢失当前主题上下文，也违反确认单的返回规则。 | 为详情、查看参考和相机保存 `returnTo` 与页面状态；从主题单进入的链路应逐级返回主题单详情。 |

## 高风险问题（Risk）

| 编号 | 位置 | 问题 | 消费者影响 | 建议修改 |
|---|---|---|---|---|
| R1 | [姿势库] →「待整理」 | 当前实现把“待整理”当作普通标签筛选；示例卡没有该标签，点击会得到无结果。 | 用户点击一个显示“3 张”的入口，却看见空页面，直接损伤信任。 | 以卡片`整理状态`过滤，不以标签文字过滤；原型中准备至少三张待整理示例卡。 |
| R2 | [导入灵感] | 导入面板预先展示“环球影城、单人、全身”等标签，视觉上像系统自动打标。 | 与“首版不依赖 AI、标签可跳过”的产品承诺冲突，用户无法判断这些词来自哪里。 | 导入面板默认无标签；增加可选的「添加标签」入口，或明确标注为用户本次可选标签，但不预填。 |
| R3 | [灵感卡详情] | 结构化标签和拍摄关键词全部以同一组 chips 展示，没有字段名称。 | 用户无法学会“拍摄关键词”可容纳游乐园、毕业、香水和随手记忆词，也无法判断何时用结构化字段。 | 编辑态按字段分组；查看态保留结构化信息优先展示，拍摄关键词以独立的「关键词」小组或折叠入口展示。 |
| R4 | [用手机照着拍] | 透明度、镜像和倒计时点击后没有可见的当前值或选中状态。 | 用户无法预测下一次点击会产生什么结果，尤其是透明度从高到低的变化不透明。 | 透明度显示当前档位或连续控制条；镜像/构图线用选中态；倒计时显示已选时长或“已取消”。 |
| R5 | [查看参考] | 只有“双指缩放 · 拖动查看细节”的常驻说明来解释手势。 | 新手未必知道可缩放；说明文本也会挤占看图空间。 | 低保真阶段保留一次性提示或 info 图标；正式 UI 通过可见的缩放控件/首次手势反馈降低依赖。 |

## 可选优化（Suggestion）

| 编号 | 位置 | 建议 | 理由 |
|---|---|---|---|
| S1 | [姿势库] 首次空态 | 空态可同时给“导入图片”和“先看官方精选”两个差异化入口；若官方内容首版不保证上线，则维持单一导入主操作。 | 给没有私库的新用户一个探索起点，但不应在素材未就绪时制造假入口。 |
| S2 | [查看参考] | 在「用手机照着拍」按钮旁保留一个更轻的“返回/继续看图”路径，无需另加说明文字。 | 强化“看图本身就是完成任务”的产品定位。 |
| S3 | [主题单列表] | 将图片数量保持为唯一元信息；人物摘要超过一行时截断。 | 保持列表扫描速度，避免把主题单做成复杂计划卡。 |

## 推荐修复顺序

1. **先修 B1、B2、B3**：补齐主题内导入、标签编辑、来源返回，确保两条主路径真实可走通。
2. **再修 R1、R2、R3**：让“低成本整理”与“拍摄关键词”在界面上说得清、用得对。
3. **最后修 R4、R5**：强化相机工具的即时状态和构图查看的可发现性。

完成前两步后，再让用户点击审核；用户确认交互无误后，才生成 `04_UI设计规格` 并回写两份 PRD 的页面级细节。
